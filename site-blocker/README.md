# site-blocker — reward dependency

The Pomodoro widget's "restriction-free mode" calls:

```bash
sudo -n /usr/local/bin/site-blocker pause <minutes>
sudo -n /usr/local/bin/site-blocker resume
```

Those calls **fail without the setup in this folder** — that's why the reward
integration needs installing alongside the timer. This is a system-wide DNS
blocklist for distracting sites (porn, social media, gambling, browser games),
blocking whole domains and subdomains through NetworkManager's dnsmasq
resolver.

## What's here

| File | Purpose |
|---|---|
| `site-blocker` | The blocker script itself — install to `/usr/local/bin/site-blocker` |
| `sudoers.d/site-blocker` | Template for the passwordless `pause`/`resume` rule |
| `systemd/site-blocker-heal.*` | Watchdog that restores expired pause windows after reboot |
| `install-site-blocker.sh` | Root installer that wires all of the above together |

The main refresh timer (`site-blocker.timer`, weekly) is generated by
`site-blocker update` itself.

## Requirements

- `sudo` with an editable `/etc/sudoers.d/`
- **NetworkManager** with dnsmasq (`dns=dnsmasq`) — the script configures this
- `curl`/`wget` for downloading blocklists (network access needed once)
- systemd (for the timers); on non-systemd systems run `pause`/`resume` manually

This uses NetworkManager's dnsmasq and disables `systemd-resolved`, so it is
most at home on Arch/Omarchy, Fedora, Ubuntu and other NetworkManager-based
desktops. It is not needed for the timer itself — only for the reward window.

## Install

```bash
cd site-blocker
chmod +x install-site-blocker.sh
sudo ./install-site-blocker.sh "$USER"
```

The installer:

1. Copies the script to `/usr/local/bin/site-blocker`
2. Generates and `visudo`-validates `/etc/sudoers.d/site-blocker` for your user
3. Installs the heal watchdog units
4. Runs `site-blocker update` (downloads lists, configures DNS, creates the
   weekly refresh timer)
5. Enables the heal timer

## Verify

```bash
sudo -n site-blocker paused
sudo -n site-blocker status
```

Both should work **without a password prompt** from your desktop user. If
`sudo -n` asks for a password, the sudoers rule is missing or wrong — the
widget will show a "Focus reward failed" notification.

## How the reward uses it

- `pause <minutes>` parks the blocklist and writes an epoch deadline to
  `/var/lib/site-blocker/pause.json`
- The widget watches that file to show the live "sites unblocked" countdown
- `resume` restores blocking immediately (panel button)
- The heal timer restores an expired/missed pause after a reboot

## Manual usage

```bash
sudo site-blocker update        # refresh lists + DNS setup
sudo site-blocker apply         # rebuild from cached lists, no download
sudo site-blocker pause 120     # unblock for 120 minutes
sudo site-blocker resume        # restore blocking now
sudo site-blocker paused        # show pause state
sudo site-blocker status        # show block count + test domains
sudo site-blocker allow DOMAIN  # allow a domain
sudo site-blocker block DOMAIN  # block an extra domain
sudo site-blocker uninstall     # remove everything and restore DNS
```

## Uninstall

```bash
sudo site-blocker uninstall
sudo rm -f /etc/sudoers.d/site-blocker
sudo rm -f /etc/systemd/system/site-blocker-heal.{service,timer}
sudo systemctl daemon-reload
```
